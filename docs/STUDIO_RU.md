# Локальная студия: первая итерация

Студия импортирует MP4, изображения и музыку, собирает короткий фильм, сохраняет варианты сцен и экспортирует проверенный MP4 локально через TypeScript/Node, Canvas и FFmpeg. Development checkout добавляет [один облачный generated take](GENERATION_RU.md) через API пользователя: candidate, preview и явное принятие отдельны от обычного монтажа. Live-проверка требует разрешения на запрос, reference и расходы.

## Первый запуск своей копии примера

Из корня исходного проекта:

```powershell
npm ci --ignore-scripts
npm run build
node dist/cli.js doctor --json
node dist/cli.js init coffee-ritual --dir projects/my-first-remix
node dist/cli.js studio projects/my-first-remix/project.json
```

Продолжайте при `ready:true`. `init` нужен только один раз для своей копии; существующий фильм открывается только командой `studio` с его `project.json`. Не редактируйте общий template ради первого remix. [Установка и исправление зависимостей](GETTING_STARTED.md) · [Продолжение с агентом](AGENT_WORKFLOW_RU.md#продолжение-существующего-фильма).

Откройте **полную ссылку сессии**, которую напечатает терминал. Сервер слушает только `127.0.0.1:4173`; остановка — Ctrl+C. Если порт занят: `node dist/cli.js studio projects/my-first-remix/project.json --port 4174`. Перезапуск создаёт новую ссылку сессии.

Нужны Node ≥22.12, Chrome/Chromium, FFmpeg с libx264/AAC и ffprobe. Проверка: `node dist/cli.js doctor --json`. На этой машине зависимости уже установлены. На другом checkout сначала выполните `npm ci --ignore-scripts`. Автоустановка системных программ не реализована.

Для macOS, вариантов HTTPS/SSH и разрешений локального агента используйте [GETTING_STARTED](GETTING_STARTED.md). Renderer поддерживает Chrome/Chromium/Edge, проверяет Canvas/PNG и сообщает `BROWSER_UNSUPPORTED` для Brave или изменённого readback. UI можно открыть в привычном браузере; `CHROME_PATH` выбирает отдельный renderer с временным профилем и включённым sandbox.

Команды выше копируют `coffee-ritual`: 20 секунд реальной съёмки эспрессо Scott Schiller (CC BY-SA 2.0), motion-титры и процедурная музыка. Атрибуция и изменения — в `CREDITS.md`, хеши и источники — в `provenance.json`. Синтетический ORBIT сохранён отдельно: `npm run studio:orbit`.

1. Выберите карточку второй сцены.
2. В поле «Выбранный исходник / дубль» выберите `first-drops.mp4`. Нажмите «Предпросмотр сцены», затем «Сохранить сцену».
3. Нажмите «Экспорт MP4». Готовый файл появится в плеере и списке экспортов.
4. Нажмите «Вернуть предыдущий вариант», затем снова экспортируйте.
5. Закройте страницу и перезапустите студию: выбранные материалы, параметры и история останутся на диске.

Основной плеер показывает **готовый экспорт**. При изменении проекта он отмечается как предыдущая версия. Верхний плеер в инспекторе показывает исходник; кнопка «Предпросмотр сцены» собирает выбранную сцену из несохранённых полей тем же движком, что и экспорт. Показаны длительность в кадрах и границы trim (правая исключена). Preview — 1080p/30 fps, без звука, не realtime; проект не сохраняет. Изменение полей помечает preview устаревшим. Для полной композиции нужен экспорт.

Обычный `render PROJECT --out NEW_DIRECTORY` через CLI/API сохраняет исходный output и отдельную MP4/manifest-копию в `exports/` проекта. Открытая видимая вкладка обновляет список примерно раз в две секунды; «Перечитать проект» тоже обновляет его. Несохранённые поля остаются в редакторе. Если студийную копию нельзя безопасно записать, результат `studioExport` и CLI предупреждают об этом; проверенный исходный output остаётся доступен. Предыдущие экспорты сохраняются.

Заголовок и вкладка показывают папку открытого `project.json`/`manifest.json` или имя отдельного JSON-файла; внутренний ID проекта не меняется. Ctrl+C при простое печатает `Local studio stopped.`, exit 0. При активном preview/export он отменяет работу, ждёт очистки и сообщает об отмене. Вкладка показывает сообщение об остановке/недоступности локального сервера и сохраняет свой черновик.

Если агент изменил файл при несохранённом черновике, «Перечитать проект» показывает обе версии без попытки сохранить старый хеш. Можно применить только изменённые локально поля поверх свежей версии, принять внешнюю с явным отказом от черновика или вернуться в редактор. Предыдущая внешняя композиция сохраняется в истории после применения черновика. Повторная внешняя правка требует нового выбора. Черновик, включая неверно заполненные поля, хранится в sessionStorage этой вкладки, когда оно доступно.

## Новый проект и свои материалы

```powershell
node dist/cli.js new --dir "my-film"
node dist/cli.js studio "my-film/project.json"
```

В интерфейсе импортируйте файлы, добавьте видео и изображения кнопками «В сцену», добавьте титр. Карточки можно перемещать, менять длительность, удалять из монтажа. Исходные файлы при удалении сцены остаются. Музыка выбирается отдельно.

Для копии реального примера: `node dist/cli.js init coffee-ritual --dir "my-coffee"`. ORBIT: `node dist/cli.js init orbit-demo --dir "my-orbit"`.

## Тот же проект из CLI и агента

```powershell
node dist/cli.js state "my-film/project.json" --json
node dist/cli.js import "my-film/project.json" --file "clips/shot.mp4" --if-match ETAG --json
node dist/cli.js edit "my-film/project.json" --action "edit.json" --if-match CURRENT_ETAG --json
node dist/cli.js validate "my-film/project.json" --json
node dist/cli.js render "my-film/project.json" --out "my-film/export-cli" --no-cache --json
node dist/cli.js verify "my-film/export-cli/output.mp4" --json
```

`import` возвращает `importedId`. Пример `edit.json` (подставьте существующие sceneId и asset ID):

```json
{
  "type": "edit-scene",
  "sceneId": "shot-id",
  "patch": {
    "asset": "media-ID-from-import",
    "trimStartSeconds": 1,
    "durationFrames": 210,
    "fit": "cover",
    "focalPoint": { "x": 0.5, "y": 0.5 }
  }
}
```

Операции: `add-scene` (`scene`), `edit-scene` (`sceneId`, `patch`), `remove-scene`, `move-scene` (`index`, с нуля), `music` (`asset`, `gainDb`, либо `provider: none/procedural`), `composition` (`video`), `restore` (`revisionId`), `restore-scene` (`revisionId`, `sceneId`). В patch значение `null` удаляет необязательное поле. Тип и ID сцены стабильны. Неизвестные поля отклоняются.

UI и CLI используют `src/project.ts`, общий JSON Schema и `loadManifest`. Внешний агент передаёт действия через `edit` с актуальным `--if-match`, сохраняя validation, блокировки и историю; accepted JSON напрямую не записывается. После внешнего изменения нажмите «Перечитать проект». Сравнение хеша манифеста помечает устаревший экспорт. Generated Accept использует тот же project API одной операцией: [generation guide](GENERATION_RU.md).

## Формат, сохранность и перенос

- v1 продолжает читаться и рендериться прежним путём. Первая правка через студию/CLI edit переводит файл в v2; предыдущая композиция попадает в историю. До этого v1 на диске не изменяется.
- v2 добавляет видеоисточники, `trimStartSeconds`, revision ID и до 100 снимков композиции. «Вернуть предыдущий вариант» восстанавливает только выбранную сцену; история монтажа восстанавливает всю композицию.
- Импорт копирует байты в `assets/<sha256>.<ext>`, записывает ожидаемый SHA-256, проверяет метаданные. Оригинальный внешний файл больше не нужен. Замена — выбор другого asset ID. Удаление/возврат сцены не удаляет медиаматериалы.
- Длительности хранятся целыми кадрами при 30 fps; UI округляет секунды к кадру. Начало trim задаётся в секундах источника, затем FFmpeg нормализует fps. Выход за длину клипа отклоняется, видео не растягивается автоматически.
- FFmpeg учитывает rotation metadata, нормализует sample aspect ratio и применяет cover/contain. Фокус cover задаётся координатами 0–1 в исходнике после поворота.
- Экспорт выполняется во временной папке и публикуется после ffprobe и полного декодирования. UI хранит каждый успешный экспорт отдельно. CLI заменяет существующий результат только с `--overwrite`; ошибка сохраняет прежний результат и отчёт.
- Для переноса достаточно `project.json`, `assets`, `PROVENANCE.md` и лицензии. `.cache`, exports и диагностические resolved-manifest не требуются. Приложенный ZIP содержит редактируемый проект и исходники.
- После аварийного завершения ОС может остаться `.edit-lock` рядом с проектом или `.render.lock` в экспорте. Сначала убедитесь, что указанный в нём процесс не работает, затем удалите именно этот stale lock. Автоматического восстановления после hard kill пока нет.

## Границы

1080p, 30 fps, 16:9/9:16; 1–60 секунд и до 12 сцен в ядре, целевой пример — 15–30 секунд и 3–4 сцены. До 24 assets; MP4 ≤512 MiB, PNG/JPEG ≤20 MiB, аудио ≤100 MiB. Видео/изображения ≤4096 пикселей по каждой стороне; входное видео ≤240 fps и ≤1 часа. Максимум project.json — 1 MiB.

В v2 используются прямые склейки; motion-анимация внутри сцены сохранена. Исходный звук видео отключён. Файловая/процедурная музыка и имеющиеся файловые voice/caption-сцены поддерживаются; поверх видеосцены субтитры/voice пока отклоняются явно. UI не вызывает онлайн Edge speech. Видео с кодеком, который браузер не декодирует, может требовать предварительного преобразования в H.264 для предпросмотра; экспорт использует FFmpeg. HDR/цветоуправление, аудиодорожки клипов, переходы v2, прокси больших файлов и полноценный многодорожечный таймлайн отложены.

Сервер предназначен для одной локальной сессии. Проверены session/Host/Origin, относительные пути, optimistic conflict и блокировки; это не независимый аудит безопасности и не сетевой сервер для размещения в интернете. Импорт и хеширование читают файл целиком в RAM. Экспорты и исходники автоматически не очищаются; сценовый кэш и ускорение не заявляются.

## Воспроизведение проверок

```powershell
npm run build
npm run check
npm run test:integration
npm run release:prepare
npm run verify:package
```

`test:integration` запускает реальные проверки Chrome/FFmpeg последовательно: рендер, trim/crop, историю, конфликты и совпадение preview с экспортом. `verify:package` устанавливает собранный архив в новый каталог, проверяет предпросмотр, возврат, хеши исходников и полный MP4. Артефакты остаются локально под `artifacts/`. Это автоматизированные сценарии, не независимое тестирование человеком.

Опциональный тест Edge (`npm run test:edge`) требует Python через `EDGE_TEST_PYTHON`; без него явно пропускается. Он использует контролируемый отказ, а не запрос к настоящему сервису. Проверка console Ctrl+C вынесена в `npm run test:windows`. Полные рендеры запускайте последовательно: при исчерпании памяти Windows FFmpeg может отказать, сохранив предыдущий результат.

Актуальный набор проверок: `npm run check` и `npm run test:integration`. Границы поддержки описаны в [COMPATIBILITY.md](COMPATIBILITY.md), подготовка поставки — в [RELEASING.md](RELEASING.md).
