# Стартовый промпт для продолжения Agent Motion Studio

Передайте агенту репозиторий и этот текст. [План](DEVELOPMENT_PLAN_RU.md) · [Матрица проверок](AGENT_VALIDATION.md).

---

Продолжи работу с учётом завершённой ContextOS-демонстрации. Сначала прочитай `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, матрицу проверок и локальный `artifacts/contextos-ad/RESULT_RU.md` со связанными результатами, если они доступны. Проверь Git status; сохраняй существующие изменения checkout, проекты, источники и историю.

Фильм из нового brief через Codex, две демонстрационные правки, restore/reopen и реальный OpenAI API-agent уже выполнены. Не создавай демонстрационный фильм заново и не повторяй выполненные задачи без найденной причины. Две правки были выбраны агентом; не объявляй их двумя новыми просьбами человека.

Текущая цель — P2 и оставшиеся проверки A1:

1. Проверь обнаружение skill и продолжение готового проекта в новой официальной модельной сессии, только если клиент доступен, авторизован и его режим разрешён. Fresh Codex native discovery уже проверен без модельного запроса. Доступный CLI использует API-key auth; при запрете платных вызовов новый модельный запрос не выполняй. Login/settings не меняй. Claude Code проверь отдельно, если установлен и авторизован; иначе запиши NOT RUN и продолжай независимую работу.
2. Используй готовый проект `projects/contextos-ad-2026-10-06/project.json` либо выданную переносимую копию. Прочитай `state`, preview разрешённой правки делай без записи. Не используй `new`/`init` для продолжения.
3. Сделай понятным путь нового пользователя: установка → doctor и устранение зависимостей → подключение skill → открытие → правка → preview → принятие → экспорт → reopen/restore. Исправляй конкретно найденные препятствия. [Guide](GETTING_STARTED.md).
4. Используй [короткий сценарий](USER_TRIAL_RU.md) для независимого человека. Собственный запуск/новая папка не являются этой проверкой. Не отправляй приглашения без поручения.
5. По AGENTS.md запускай `npm run check`, а для project/server/studio/renderer — последовательный `npm run test:integration`. Изменения поставки проверяй локальной упаковкой и установленным consumer. Не повторяй художественную демонстрацию вместо проверки изменённого поведения.

Технические границы:

- Accepted edits, imports и restore — только через `src/project.ts` и общие CLI/API operations. Не перезаписывай принятый JSON, исходники или историю напрямую.
- Preview использует общий encoder и не сохраняет draft. При conflict перечитай актуальное состояние и повтори preview; не применяй старый ETag вслепую.
- Сохрани IDs/type, duration/trim/crop и v1/v2 compatibility. Рендеры в новые папки, последовательно.
- Сохрани loopback, session/Origin/Host/asset-path checks и plain HTML/CSS/JS. Credentials/session URLs не включай в отчёты.
- Optional Replicate track уже реализован offline; live billing/output/full workflow остаются отдельной проверкой. Не трать бюджет, не загружай reference и не подменяй production mock-ом.
- Платные вызовы, uploads, релизы и публикация требуют соответствующего поручения пользователя. Ранее данное конкретное разрешение сохраняется.

В результате покажи, что стало проще пользователю, фактические команды/exit codes, сохранность существующего проекта и оставшиеся непроверенные пункты. Passing encode не доказывает художественное качество, удобство независимого человека или спрос. Не называй всю поддержку клиентов завершённой.

---

Данные доступа можно приложить без секретов: официальный клиент/версия, режим подписка или API, путь к готовому проекту, разрешённая правка, внешние вызовы/бюджет и публикация. Пустое поле не даёт новое разрешение и не блокирует независимую локальную работу.
