# Стартовый промпт для агента: Agent Motion Studio

Передай агенту репозиторий и этот текст. Полный план: [DEVELOPMENT_PLAN_RU.md](DEVELOPMENT_PLAN_RU.md).

---

Продолжи разработку Agent Motion Studio по `docs/DEVELOPMENT_PLAN_RU.md`. Текущая цель поручения — этапы P0 и P1: один настоящий генерируемый дубль существующей video scene с сохранённым job, предпросмотром, явным принятием, локальным экспортом и восстановлением предыдущего дубля.

Конечное направление продукта: бесплатная открытая локальная студия коротких AI-фильмов, использующая AI пользователя через официального внешнего агента, API-ключи и поддерживаемые provider integrations. Облачные вычисления используют тарифы пользователя. Локальный export уже существует; локальный inference видеомодели — отдельная будущая возможность.

Сначала прочитай `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, полный план и затрагиваемый код. Проверь текущую ветку, Git status, версии инструментов и исходные checks. Сохрани посторонние изменения и пользовательские проекты. Не сбрасывай checkout к commit из плана: он указан как историческая отправная точка.

Работай небольшими проверяемыми частями. Обычные технические решения принимай самостоятельно в пределах цели; не спрашивай подтверждение на каждую правку. Исследуй официальные документы и выбери один video provider по доступу пользователя, подходящей длительности/reference и возможности отслеживать job после restart. Не создавай одновременно несколько adapters, собственный чат, billing или новый UI framework.

Технические инварианты:

- `src/project.ts` владеет всеми принятыми изменениями. Не записывай accepted project JSON напрямую из generation/UI/CLI.
- Первая версия заменяет существующую video scene на новый video take; сохраняет её duration. Новый source trim по умолчанию 0, fit/focal видны пользователю.
- Candidate хранится отдельно от accepted manifest. Его preview не меняет project bytes, ETag, registry или history.
- Accept проверяет fingerprint просмотренного candidate draft; изменение trim/crop/контекста требует нового preview. Project ETag не заменяет эту проверку.
- Accept регистрирует immutable source и меняет сцену одной принятой project operation. Повтор/сбой между commit и job ack не должен повторно применять дубль.
- Используй общий preview/export encoder. Не дублируй FFmpeg timing/crop logic.
- Долгий remote job не держит project edit lock. При принятии перепроверяй актуальную сцену, ETag и повторную гонку UI/агента.
- Сохраняй remote ID, параметры и состояние. При неопределённом submit не выполняй blind retry. Повтор download не создаёт новую генерацию.
- Production не переключается на mock при отсутствии ключа. Controlled provider используется только в тестах.
- Credentials остаются server-side вне проекта. Не публикуй keys, session URLs, signed URLs, private prompts и файлы пользователя.
- Сохраняй loopback/session/Host/Origin/path checks и совместимость v1/v2.
- Обнови CLI/skill и их references под реальный v2 workflow, чтобы внешнему агенту не приходилось обходить project API.

Не выполняй платные запросы, uploads пользовательского reference, публикацию, push/tag/release без уже данного разрешения на конкретное действие. Наличие ключа в environment не означает разрешённый бюджет. Если разрешение на live-run отсутствует, доведи adapter, state machine, candidate workflow, UI/CLI, offline tests и инструкции до проверяемого состояния. Подготовь конкретный request с моделью, reference, параметрами и оценкой расходов; только после этого запроси недостающие данные для последнего live acceptance шага. Не останавливай всю разработку из-за отсутствия ключа и не называй mocks настоящей генерацией.

Проверяй observable behavior: число remote submissions, restart, damaged/expired downloads, preview без записи, repeated Accept, external-edit conflicts через настоящий UI, сохранность sources/history и decoded frames остальных/восстановленных сцен. Media tests запускай последовательно. После изменений project/server/studio/renderer выполни `npm run check` и `npm run test:integration`; при упаковке последовательно `npm run release:prepare` и `npm run verify:package`. Live tests должны быть отдельным явным запуском.

Если подтвердится описанный в плане риск изменения source во время full export, исправь его узко с regression. Не выдавай статическое предположение за воспроизведённый дефект.

В результате передай работающий сценарий, команды запуска и возобновления, изменения кода, фактические результаты tests, артефакты original/changed/restored при состоявшемся live-run, известные расходы и NOT RUN. Финальный статус должен отличать «offline contract verified», «real provider verified» и «full workflow verified».

P2–P5 — последующие вехи. Не реализуй их автоматически в рамках этого поручения. После P1 следующий результат — независимая пользовательская попытка по README.
