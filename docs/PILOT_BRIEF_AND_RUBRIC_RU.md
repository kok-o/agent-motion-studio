## 1. Один нейтральный бриф для обоих путей

Покажите функцию Agent Motion Studio: просмотр сцены перед сохранением, экспорт и возврат к предыдущему варианту. Это **self-run о собственном продукте**, без внешнего заказчика и без подтверждения независимого спроса. Аудитория — разработчик, которому нужен короткий ролик для объяснения этой функции; место использования — локальный предварительный просмотр страницы документации. Публикация не входит в пилот.

Создайте новый фильм 16:9, 1920×1080, 30 fps, 20 секунд / 600 кадров, четыре сцены по 150 кадров. Палитра: фон `#101820`, текст `#FFFFFF`, акцент `#FEE715`. Никаких сравнительных обещаний о качестве, цене, скорости или недостатках других инструментов.

| Сцена / ID | Интервал | Точный текст | Визуальная задача |
| --- | --- | --- | --- |
| 1 / opening | 0–5 с | «Нужно изменить одну сцену» | Показать четыре карточки сцен и выделить одну |
| 2 / preview | 5–10 с | «Посмотреть перед сохранением» | Использовать существующий screenshot студии; обозначить его как статичный экран, без имитации настоящего клика |
| 3 / export | 10–15 с | «Сохранить вариант и экспортировать MP4» | Показать схему «сцена → вариант → MP4»; это объясняющая графика, не запись выполненного экспорта |
| 4 / restore | 15–20 с | «Вернуться к предыдущему варианту» | Показать два варианта выбранной сцены и сохранённые соседние карточки |

Разрешённый общий пакет:

- Screenshot [studio.png](media/studio.png) из репозитория; одинаковые bytes для обоих путей. Не показывать выдуманный интерфейс или возможность, которой нет в продукте.
- Один готовый музыкальный [WAV](../examples/orbit-demo/assets/c01c70f221e3ff534b5ce8eef32c93936a8f8f57185dbc4768dfbd5ae6a9ee76.wav), начальный gain −18 dB. [Происхождение](../examples/orbit-demo/PROVENANCE.md), [MIT для этих assets](../examples/orbit-demo/LICENSE). Передать обоим один и тот же файл, сохранить notices. Narration не требуется.
- Текст и палитра выше. Новые внешние медиа, neural generation и загрузка материалов не нужны. Существующие готовые фильмы не подменяют новый brief.

До запуска сохранить SHA-256 общего пакета и его copy, storyboard и ограничения. Оба пути получают этот brief без подсказок, доступных только одному инструменту. Если человек выберет другую реальную функцию или материалы, сначала зафиксировать новую общую версию брифа для обоих путей.

## 2. Условия сравнения и порядок работы

AMS сравнивается с **/brag full + HyperFrames** по плану. До запуска записать exact AMS SHA, версии/commits альтернативы и skills, ОС/инструменты, официальный клиент, модель и настройки, лимиты и допустимую передачу материалов. Использовать независимые рабочие папки и свежие сессии без переноса решения между путями. Порядок путей выбрать и записать заранее. Сохранить штатные typed edits/Studio альтернативы, если они доступны в выбранной версии; не сводить её искусственно к переписыванию HTML.

Один клиент/модель и одинаковый бюджет предпочтительны. Если это невозможно, раскрыть различие; результат нельзя приписывать только редактору. Старый опубликованный kit и новый PR runtime имеют разные stamps: не выдавать один за другой. Не устанавливать внешние skills и не начинать model runs в рамках подготовки P4.

1. Отдельно измерить setup до готовности инструментов, затем создание первого MP4 и просмотр человеком.
2. После просмотра человек формулирует **две собственные просьбы**, последовательно. Записать точные слова и желаемые неизменные решения; одинаковую просьбу передать обоим путям. Сохранить baseline и каждый результат в отдельном output. Пока просьб нет, поля остаются NOT RUN.
3. Человек смотрит движение и слушает каждый результат. Технический PASS не заменяет его оценку. Исправления для достижения пригодности тоже входят во время, расходы и число вмешательств.
4. Выполнить согласованный restore к записанной ревизии до выбранной правки, экспорт и reopen в новой сессии, затем продолжить проект. Сохранить полный проект с assets, `.history/` и прежними exports. Для альтернативы записать её фактический механизм возврата и ограничения.
5. Оба пути довести до одинакового критерия человека либо записать blocker/достигнутый лимит и частичный результат. Не скрывать неудачные попытки или помощь разработчика.

**Отдельные технические проверки, не выбор человека:** при необходимости после основного цикла можно проверить shortening 150→120 кадров с сохранением текста/источника; gain-only −18→−22 dB с сохранением file asset; aspect-only с сохранением style/safeArea. Эти фиксированные проверки не засчитываются как две собственные просьбы человека и не заменяют просмотр/прослушивание. Их время и расходы учитывать отдельно.

## 3. Человеческая рубрика и приёмка

Шкала: 1 — непригодно; 2 — требует существенной переделки; 3 — пригодно после конкретных исправлений; 4 — пригодно с небольшими замечаниями; 5 — пригодно без замечаний. Человек указывает причину и таймкод каждого замечания. Желательно показывать результаты с нейтральными метками A/B и записать, знал ли оценщик инструмент. Результаты одного self-run не доказывают превосходство, спрос или экономию.

Надёжность правок фиксируется отдельно: выполнен ли запрос, какие не запрошенные решения изменились, сохранены ли источники и предыдущие варианты, прошли ли restore/reopen. ## 4. Время, помощь и расходы

Все поля ниже пусты до реального запуска. **Локальный renderer не взимает API-плату; это не означает нулевую стоимость агентной работы.** Подписку, usage API, optional media и инфраструктуру учитывать раздельно. Отсутствие invoice/usage означает UNKNOWN, а не 0. Для подписки записать тариф/период и использованную квоту, не выдумывать цену отдельного запроса. Оценку по usage пометить как оценку с датой/источником цены; invoice хранить отдельно. Новые платные calls/передача материалов требуют отдельного разрешения.

| --- | --- | --- |

| Первый MP4: активное время / model wait / render wait | NOT RUN | NOT RUN |

Журнал попыток: путь, этап, начало/конец, request/operation ID без credentials, outcome/exit code, usage/расход, причина retry и помощь. Неуспешные calls и неопределённый исход сохранять в сумме и резерве; не объявлять общий итог меньше подтверждённого расхода. Не продолжать за согласованным лимитом. Для post-commit ошибок и generated Accept использовать [контракт проекта](MANIFEST.md) и [receipt recovery](GENERATION_RU.md), без слепого replay.

Локальные доказательства: frozen brief/input hashes, версии/настройки, журналы, оригинальный/изменённые/восстановленный MP4, contact sheets, переносимые проекты и человеческие ответы. Публичный отчёт — только после отдельного поручения, без ключей, session/signed URLs, личных материалов и private prompts. На момент P4 пилот, расходы пилота и человеческая приёмка **NOT RUN**.
