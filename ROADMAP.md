# Development navigation

The product goal is an open-source local video studio operated through the user's own official agent or API access: brief → film → requested edits → MP4 and an editable project.

There is one execution plan: [PLAN_V0.2_RU.md](docs/PLAN_V0.2_RU.md). Its current section defines the next ordered outcomes and acceptance gates: editing reliability, a real comparative pilot, targeted creative/QA/setup improvements, and an evidence-based renderer decision. The local v0.2 iteration and accepted fastgrep remain completed history, not new assignments. The package is still version 0.1.0.

[STATUS.md](docs/STATUS.md) is the current-state summary. [AGENT_VALIDATION.md](docs/AGENT_VALIDATION.md) retains detailed evidence and client limits. This file is a navigation page, not a second backlog.

[Motion-stack sources](docs/MOTION_STACK_SOURCES.md) lists /brag and all 20 entries from the shared collection, with review depth and reuse boundaries. It is a reference catalog, not an install list. Writing the plan does not automatically start implementation, spending, external skill installation, new Issues or publication.

Current result: different briefs and common edits verified from an installed package, editable object compositions, RU/EN studio and a fastgrep accepted after two human-selected visual corrections and a sound revision. Preserve the demonstrated films and optional video-provider implementation. Independent-user trials and additional clients/operating systems remain separate unverified items.

Later choices — measured rendering optimization, other clients/providers, optional local video inference and a stable release — depend on the results of that workflow. They are not automatic tasks for this iteration. Paid calls, uploads and publication keep their existing authorization boundaries.

Old engineering specifications remain under `docs/archive/` in the source checkout for targeted reference. Do not restart their historical A1/P0/P1 assignments.
